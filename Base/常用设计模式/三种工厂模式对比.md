# 简单工厂 vs 工厂方法 vs 抽象工厂

## 概述

GoF 设计模式中涉及三种"工厂"模式，它们易于混淆。iOS 中的**类簇**（Class Cluster）也常被误归类为抽象工厂。本文从 GoF 原始定义出发，做系统对比辨析。

---

## 一、三种工厂模式总览

| 维度 | 简单工厂（Simple Factory） | 工厂方法（Factory Method） | 抽象工厂（Abstract Factory） |
|------|--------------------------|--------------------------|----------------------------|
| **核心思想** | 一个工厂类根据参数返回不同产品 | 定义创建接口，由子类决定实例化哪个类 | 创建**一系列相关或依赖的**产品对象 |
| **产品数量** | 一种产品（同一基类/接口） | 一种产品（同一基类/接口） | **多种不同产品**（一族产品） |
| **创建方式** | 一个静态方法 + 参数判断 | 各子类各自实现工厂方法 | 每个具体工厂创建一整套产品 |
| **扩展方式** | 修改工厂类（添加 if-else） | 新增子类（开放封闭原则） | 新增工厂实现一整套产品族 |
| **产品接口** | 单一接口 | 单一接口 | **多个不同接口**（产品族） |
| **是否 GoF 正式模式** | ❌（GoF 未收录，但广泛使用） | ✅ | ✅ |
| **示例** | `NSArray arrayWithObject:` 返回不同子类 | `-[Document open]` 返回 PDF/Word/HTML | UI 工厂：创建 Button + TextField + Menu |

---

## 二、GoF 原始定义

### 工厂方法（Factory Method）

> Define an interface for creating an object, but let subclasses decide which class to instantiate. Factory Method lets a class defer instantiation to subclasses.
>
> 定义创建对象的接口，由子类决定实例化哪个类。工厂方法让类将实例化延迟到子类。

**核心特征**：
- 定义一个抽象的创建方法（工厂方法）
- 由子类实现该创建方法，决定返回哪个具体产品
- 调用者通过多态，在运行时获得具体产品

### 抽象工厂（Abstract Factory）

> Provide an interface for creating families of related or dependent objects without specifying their concrete classes.
>
> 提供一个创建**一族相关或依赖对象**的接口，而无需指定具体类。

**核心特征**：
- 创建的不是一个产品，而是一个**产品族**（多个不同接口的产品）
- 每个具体工厂创建一整套产品（所有产品之间有关联关系）
- 客户端通过抽象工厂接口操作，不关心具体平台

### 简单工厂（Simple Factory）

不是 GoF 正式收录的模式，但被广泛使用。核心特征：

> A class that creates objects based on input parameters, hiding the instantiation logic from the client.
>
> 一个类根据输入参数创建对象，将实例化逻辑隐藏在客户端之外。

## 三、示意图对比

```
┌─────────────────────────────────────────────────────────────────┐
│                  简单工厂（Simple Factory）                       │
│                                                                 │
│  工厂类.factoryMethod:                                           │
│     参数 A ──→ 具体产品 A（同一父类）                             │
│     参数 B ──→ 具体产品 B（同一父类）                             │
│     参数 C ──→ 具体产品 C（同一父类）                             │
│                                                                 │
│  ⚡ 调用者只需知道工厂类 + 参数，不需要知道具体子类                  │
│  ⚡ 类簇属于此类                                                │
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│               工厂方法（Factory Method）                          │
│                                                                 │
│  Creator（抽象创建者）                                           │
│    + factoryMethod() ← 抽象方法                                  │
│        ↑              ↑              ↑                          │
│  ConcreteCreatorA  ConcreteCreatorB  ConcreteCreatorC            │
│    → 产品 A           → 产品 B        → 产品 C                   │
│                                                                 │
│  ⚡ 延迟实例化到子类，符合开放封闭原则                              │
│  ⚡ 调用者知道自己在用哪个 Creator                                 │
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│                抽象工厂（Abstract Factory）                       │
│                                                                 │

│    + createButton()    → 返回 Button 接口                        │
│    + createTextField() → 返回 TextField 接口                     │
│    + createMenu()      → 返回 Menu 接口                          │
│       ↑                           ↑                              │
│  Windows工厂                  Mac工厂                             │
│    → Windows Button          → Mac Button                       │
│    → Windows TextField       → Mac TextField                    │
│    → Windows Menu            → Mac Menu                         │
│                                                                 │
│  ⚡ 创建一整套"产品族"（多个不同接口）                              │
│  ⚡ 调用者通过抽象工厂接口操作，不关心是哪个平台                    │
└─────────────────────────────────────────────────────────────────┘
```

## 四、代码示例对比

### 4.1 简单工厂（Simple Factory）

```objc
// 一个静态方法 + 参数判断，返回不同子类
// 类簇（Class Cluster）的实现方式与此完全一致

@implementation ImageFactory
+ (UIImage *)imageForType:(ImageType)type {
    switch (type) {
        case Thumbnail: return [ThumbnailImage new];
        case FullSize:  return [FullSizeImage new];
        case Blurred:   return [BlurredImage new];
    }
}
@end

// 调用：ImageFactory 决定返回哪个子类
UIImage *img = [ImageFactory imageForType:Thumbnail];
```

**缺点**：每新增一种产品，需要修改工厂类（违反开闭原则）。

### 4.2 工厂方法（Factory Method）

```objc
// 定义抽象基类，由子类决定创建哪个具体对象
@interface Document : NSObject
- (Document *)open; // 工厂方法，子类实现
@end

@interface PDFDocument : Document
- (PDFDocument *)open { return [PDFDocument new]; }
@end

@interface WordDocument : Document
- (WordDocument *)open { return [WordDocument new]; }
@end

// 调用：多态，运行时决定具体类型
Document *doc = [someDoc open]; // 返回 PDF 或 Word
```

**优点**：符合开闭原则，新增产品时只需要新增子类，不修改现有代码。
**缺点**：每增加一个产品，也要增加一个子工厂。

### 4.3 抽象工厂（Abstract Factory）

```objc
// 定义一整套产品族接口
@protocol GUIFactory <NSObject>
- (Button *)createButton;       // 返回 Button 类型
- (TextField *)createTextField; // 返回 TextField 类型
- (Menu *)createMenu;           // 返回 Menu 类型
@end

// Windows 产品族
@interface WindowsFactory : NSObject <GUIFactory>
- (WindowsButton *)createButton { return [WindowsButton new]; }
- (WindowsTextField *)createTextField { return [WindowsTextField new]; }
- (WindowsMenu *)createMenu { return [WindowsMenu new]; }
@end

// Mac 产品族
@interface MacFactory : NSObject <GUIFactory>
- (MacButton *)createButton { return [MacButton new]; }
- (MacTextField *)createTextField { return [MacTextField new]; }
- (MacMenu *)createMenu { return [MacMenu new]; }
@end

// 调用：选择某个工厂，创建一整套产品
id<GUIFactory> factory = isMac ? [MacFactory new] : [WindowsFactory new];
Button *btn = [factory createButton];       // MacButton 或 WindowsButton
TextField *tf = [factory createTextField];  // MacTextField 或 WindowsTextField
Menu *menu = [factory createMenu];          // MacMenu 或 WindowsMenu
// ⚡ 注意：createButton 和 createTextField 返回的是不同接口！
```

**核心区别**：抽象工厂创建的是**多个不同接口的产品**，而简单工厂和工厂方法只创建**同一接口的产品**。

## 五、iOS 类簇的归属分析

### 5.1 类簇是什么

类簇（Class Cluster）是 iOS Foundation 中的设计模式：

```objc
// 都是 NSArray 类型，但实际返回不同子类
NSArray *empty  = @[];                    // → __NSArray0
NSArray *single = @[@"hi"];              // → __NSSingleObjectArrayI
NSArray *normal = @[@"a", @"b"];         // → __NSArrayI
NSMutableArray *mutable = [NSMutableArray array]; // → __NSArrayM
```

### 5.2 类簇 vs 三种工厂模式

```
类簇的特征对照：
────────────────────────────────────────────────────
1. ✅ 一个工厂入口（NSArray / NSMutableArray 类方法）
2. ✅ 传入参数决定返回哪个子类（元素个数、可变性）
3. ✅ 所有子类实现同一接口（count, objectAtIndex:）
4. ✅ 调用者不知道具体子类
5. ❌ 不涉及子类工厂方法（类簇没有 NSArray 的子类去决策）
6. ❌ 不涉及多个产品接口（所有子类都是 NSArray 类型）
────────────────────────────────────────────────────
```

| 类簇特征 | 匹配简单工厂 | 匹配工厂方法 | 匹配抽象工厂 |
|---------|------------|------------|------------|
| 一个创建方法根据参数返回不同子类 | ✅ | ❌ | ❌ |
| 返回所有产品遵循同一基类接口 | ✅ | ✅ | ❌（需多个接口） |
| 只有一个工厂（NSArray 类本身） | ✅ | ❌（需多个子工厂） | ❌（需多个工厂族） |
| 不创建"一族产品" | ✅ | ✅ | ❌（核心是产品族） |

### 5.3 结论

**类簇 = 简单工厂**（Simple Factory）

- **类簇 ≠ 工厂方法**：工厂方法的核心是由**子类决定实例化哪个类**，而类簇的具体子类是私有的，调用者无法创建子类去决策
- **类簇 ≠ 抽象工厂**：抽象工厂的核心是创建**一族多个不同接口的产品**，类簇只返回单一接口的实现
- **类簇符合简单工厂**：一个类方法 + 参数判断 + 返回同一接口的不同实现

> 很多 Apple 资料将类簇归类于"抽象工厂模式"，原因是强调"隐藏具体子类"这一面，而非 GoF 原意中的"产品族"概念。从 GoF 严格定义来看，类簇是简单工厂模式。

## 六、类簇与简单工厂的关系

```objc
// 简单工厂：一个静态方法 + 参数判断，返回不同子类
+ (Vehicle *)createVehicle:(VehicleType)type {
    if (type == Car)   return [Car new];
    if (type == Truck) return [Truck new];
    if (type == Bus)   return [Bus new];
}

// 类簇的行为与其完全一致
+ (NSArray *)arrayWithObjects:(id *)objs count:(NSUInteger)cnt {
    if (cnt == 0) return [__NSArray0 new];           // 空数组
    if (cnt == 1) return [__NSSingleObjectArrayI new]; // 单元素
    return [__NSArrayI new];                           // 普通数组
}
```

## 七、选择指南

| 场景 | 推荐模式 | 原因 |
|------|---------|------|
| 创建逻辑简单，只有少数产品变体 | 简单工厂 | 够用，不增加复杂度 |
| 产品种类可能持续增加，希望符合开闭原则 | 工厂方法 | 新增产品只需新增子类 |
| 需要创建一整套相关产品或跨平台产品族 | 抽象工厂 | 保证不同产品之间的一致性 |
| 不想暴露复杂子类体系给调用者 | 简单工厂（类簇） | 调用者只需知道一个工厂入口 |
| 创建逻辑需要由子类覆写 / 多态决定 | 工厂方法 | 利用继承的运行时多态 |
