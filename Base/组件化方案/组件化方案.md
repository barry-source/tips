## 一、模块化 vs 组件化

| 概念 | 模块化（Modularization） | 组件化（Componentization） |
|------|------------------------|--------------------------|
| **粒度** | 较大（按功能模块划分） | 较小（按可复用组件划分） |
| **目标** | 解耦业务，分层清晰 | 复用为主，业务无关 |
| **交付方式** | 源码 / Framework | 源码 / CocoaPods / SPM |
| **依赖关系** | 模块间可相互依赖 | 组件间尽量无依赖 |
| **典型示例** | 登录模块、订单模块 | 网络库、图片加载库、UI 组件库 |

- 模块化关注的是按照功能将系统划分成不同的模块，强调减少耦合性和提高功能的独立性，但是每个模块不一定完全具备独立性
- 组件化强调高度封装，独立性和复用性，组件是更高层次的功能单元，往往是可独立开发，测试和部署的
- 两者不是对立的，模块化和组件化可以结合使用，逐步将模块划分推进到组件划分，从而提高系统的的可维护性，可扩展性和开发效率

## 三、组件化通信方案

### 3.1 URL Router 方案（MGJRouter / JLRoutes）

```objc
// ════════════ 1. 注册路由 ════════════
[MGJRouter registerURLPattern:@"app://user/detail/:id" toHandler:^(NSDictionary *routerParameters) {
    // routerParameters 包含 URL 中的所有参数
    NSString *userId = routerParameters[@"id"];                 // URL 路径参数
    NSString *source = routerParameters[@"source"];              // URL query 参数
    id userInfo = routerParameters[MGJRouterParameterUserInfo]; // 额外字典参数
    void(^completion)(id) = routerParameters[MGJRouterParameterCompletion]; // 回调

    UserDetailViewController *vc = [[UserDetailViewController alloc] initWithUserId:userId];
    [[UIApplication sharedApplication].keyWindow.rootViewController pushViewController:vc];
}];

// ════════════ 2. 调用路由 - 传参 ════════════
// 方式 A：URL 路径 + query 传参
[MGJRouter openURL:@"app://user/detail/123?source=home"];

// 方式 B：通过 userInfo 字典传参（支持复杂对象）
[MGJRouter openURL:@"app://user/detail/123"
       withUserInfo:@{@"source": @"home", @"data": aModelObject}
         completion:nil];

// ════════════ 3. 调用路由 - 传参 + 回调 ════════════
[MGJRouter openURL:@"app://order/create"
       withUserInfo:@{@"productId": @"p001", @"quantity": @2}
         completion:^(id result) {
    // 回调：订单创建完成后被调用
    NSLog(@"订单创建结果: %@", result);
}];
```

**参数传递方式**：

| 参数来源 | 示例 | 类型 | 适用场景 |
|---------|------|------|---------|
| **URL 路径** | `user/123` | NSString | 必须参数（如 ID） |
| **URL Query** | `?source=home` | NSString | 可选参数 |
| **UserInfo** | `withUserInfo:@{...}` | NSDictionary | 复杂对象参数 |
| **Completion** | `completion:^(id){}` | Block | 回调/结果返回 |

**回调处理**：
- 通过 `MGJRouterParameterCompletion` key 获取 completion block
- 调用方以 block 形式传入，目标方在合适时机调用
- 支持异步回调（等页面返回后触发）

```objc
// 目标方获取回调并执行
void(^completion)(id) = routerParameters[MGJRouterParameterCompletion];
if (completion) {
    completion(@{@"orderId": @"order001", @"status": @"success"});
}
```

### 3.2 Target-Action 方案（CTMediator）

```objc
// ════════════ 1. Target 定义 ════════════
@interface Target_Order : NSObject

// Action 方法：参数统一用 NSDictionary，返回值统一用 id
- (UIViewController *)Action_nativeCreateOrder:(NSDictionary *)params;

@end

@implementation Target_Order

- (UIViewController *)Action_nativeCreateOrder:(NSDictionary *)params {
    NSString *productId = params[@"productId"];
    NSInteger quantity = [params[@"quantity"] integerValue];
    void(^callback)(NSDictionary *) = params[@"callback"];  // 回调 Block

    OrderCreateVC *vc = [[OrderCreateVC alloc] initWithProductId:productId quantity:quantity];
    vc.completion = ^(NSDictionary *result) {
        if (callback) callback(result);
    };
    return vc;
}

@end

// ════════════ 2. CTMediator 分类封装（推荐） ════════════
// 通过 CTMediator 分类提供类型安全的方法
@interface CTMediator (OrderActions)

- (UIViewController *)createOrderWithProductId:(NSString *)productId
                                      quantity:(NSInteger)quantity
                                      callback:(void(^)(NSDictionary *result))callback;

@end

@implementation CTMediator (OrderActions)

- (UIViewController *)createOrderWithProductId:(NSString *)productId
                                      quantity:(NSInteger)quantity
                                      callback:(void(^)(NSDictionary *result))callback {
    // 内部通过 Runtime 调用 Target_Order 的 Action_nativeCreateOrder:
    return [self performTarget:@"Order"
                        action:@"nativeCreateOrder"
                        params:@{
                            @"productId": productId ?: @"",
                            @"quantity": @(quantity),
                            @"callback": callback ?: ^(NSDictionary *r){}
                        }];
}

@end

// ════════════ 3. 调用方使用 ════════════
// 方式 A：直接通过分类方法调用（推荐，类型安全）
CTMediator *mediator = [[CTMediator alloc] init];
UIViewController *vc = [mediator createOrderWithProductId:@"p001"
                                                 quantity:2
                                                 callback:^(NSDictionary *result) {
    NSLog(@"订单创建结果: %@", result);
}];
[self.navigationController pushViewController:vc animated:YES];

// 方式 B：直接调用（不推荐，字符串硬编码）
UIViewController *vc = [mediator performTarget:@"Order"
                                        action:@"nativeCreateOrder"
                                        params:@{@"productId": @"p001", @"quantity": @2}];
```

**参数传递方式**：

| 方式 | 说明 | 优点 | 缺点 |
|------|------|------|------|
| **原始 params 字典** | Target 的 Action 接收 NSDictionary | 通用，不需要额外代码 | 类型不安全 |
| **CTMediator 分类封装** | 在分类中提供类型安全的方法 | ✅ 编译检查 + 自动补全 | 需为每个 Target 写分类 |

**回调处理**：
- 将 callback block 放入 params 字典传递给 Target
- Target 在执行结果时调用 block
- 通过 CTMediator 分类封装，调用方用 block 参数传递，代码清晰

```objc
// 参数中包含 callback 的典型用法
params = @{
    @"productId": @"p001",
    @"quantity": @2,
    @"callback": ^(NSDictionary *result) {
        // 回调
    }
};
```

### 3.3 Protocol-Class 方案（BeeHive / 自定义 Service Locator）

```objc
// ════════════ 1. 定义协议（含传参和回调） ════════════
@protocol OrderServiceProtocol <NSObject>

// 方法参数直接声明，类型安全
- (UIViewController *)createOrderWithProductId:(NSString *)productId
                                      quantity:(NSInteger)quantity
                                      callback:(void(^)(NSDictionary *result))callback;

// 带进度的回调
- (void)uploadImage:(UIImage *)image
           progress:(void(^)(float progress))progressBlock
         completion:(void(^)(NSString *url, NSError *error))completion;

// 返回值为协议类型（进一步解耦）
- (id<OrderProtocol>)getOrderWithId:(NSString *)orderId;

@end

// ════════════ 2. 实现协议 ════════════
@interface OrderServiceImpl : NSObject <OrderServiceProtocol>
@end

@implementation OrderServiceImpl

- (UIViewController *)createOrderWithProductId:(NSString *)productId
                                      quantity:(NSInteger)quantity
                                      callback:(void(^)(NSDictionary *))callback {
    OrderCreateVC *vc = [[OrderCreateVC alloc] initWithProductId:productId quantity:quantity];
    vc.onOrderCreated = ^(NSDictionary *result) {
        if (callback) callback(result);
    };
    return vc;
}

- (void)uploadImage:(UIImage *)image
           progress:(void(^)(float))progressBlock
         completion:(void(^)(NSString *, NSError *))completion {
    // 上传逻辑
}

@end

// ════════════ 3. 注册服务 ════════════
// 在 +load 或 App 启动时注册
[ServiceLocator registerService:@protocol(OrderServiceProtocol)
                     withClass:[OrderServiceImpl class]];

// 或使用 BeeHive
[BeeHive registerService:@protocol(OrderServiceProtocol)
                   class:[OrderServiceImpl class]];

// ════════════ 4. 调用方使用 ════════════
id<OrderServiceProtocol> service = [ServiceLocator service:@protocol(OrderServiceProtocol)];
UIViewController *vc = [service createOrderWithProductId:@"p001"
                                                quantity:2
                                                callback:^(NSDictionary *result) {
    NSLog(@"订单结果: %@", result);
}];

// 多项回调
[service uploadImage:image progress:^(float progress) {
    NSLog(@"上传进度: %.1f%%", progress * 100);
} completion:^(NSString *url, NSError *error) {
    if (url) NSLog(@"上传成功: %@", url);
}];
```

**参数传递方式**：

| 方式 | 说明 | 优点 |
|------|------|------|
| **协议方法参数** | 直接在协议方法中声明参数 | ✅ 编译时类型安全 |
| **协议方法返回值** | 返回值可以是协议/block | ✅ 编译时类型安全 |

**回调处理**：
- 直接在协议方法中声明 block 参数
- 支持多个回调（如 progress + completion）
- 编译时类型检查，Xcode 自动补全
- 最推荐的方案

### 3.4 三种方案传参与回调对比

| 维度 | URL Router | Target-Action | Protocol-Class |
|------|-----------|---------------|---------------|
| **参数传递方式** | URL Path + Query + UserInfo 字典 | params NSDictionary | 协议方法参数 |
| **参数类型安全** | ❌ 字典，编译不检查 | ❌ 字典，编译不检查 | ✅ 编译时类型安全 |
| **参数自动补全** | ❌ 不支持 | ❌ 不支持 | ✅ 支持 |
| **复杂对象传参** | ✅ UserInfo 可传任意对象 | ✅ Dictionary 可包装 | ✅ 直接传 |
| **回调处理方式** | completion block 放字典 | callback block 放字典 | block 做协议方法参数 |
| **多个回调** | ❌ 仅支持一个 completion | ❌ 需自行封装 | ✅ 任意多个 |
| **返回值处理** | ❌ 只能通过回调 | ❌ 通过 Runtime 转 | ✅ 直接返回值 |
| **可读性** | 差 | 中 | 优 |
| **推荐指数** | ⭐⭐ | ⭐⭐⭐ | ⭐⭐⭐⭐⭐ |

### 4.1 CTMediator 源码解析

CTMediator（casatwy 版）是 Target-Action 方案在生产环境中的经典实现。

#### 完整源码

```objc
// LGMediator.h
#import <UIKit/UIKit.h>

@interface LGMediator : NSObject

// 本地组件间调用
- (id)performTarget:(NSString *)targetName
             action:(NSString *)actionName
             params:(NSDictionary *)params
  shouldCacheTarget:(BOOL)shouldCacheTarget;

// 远程 URL 调用（scheme://target/action?params）
- (id)performActionWithUrl:(NSURL *)url
                completion:(void(^)(NSDictionary *info))completion;

// 释放缓存的 Target
- (void)releaseCachedTargetWithTargetName:(NSString *)targetName;

@end
```

```objc
// LGMediator.m
#import "LGMediator.h"
#import <objc/runtime.h>

NSString * const kLGMediatorParamsKeySwiftTargetModuleName = @"kLGMediatorParamsKeySwiftTargetModuleName";

@interface LGMediator ()
@property (nonatomic, strong) NSMutableDictionary *cachedTarget;
@end

@implementation LGMediator

#pragma mark - public methods
+ (instancetype)sharedInstance
{
    static LGMediator *mediator;
    static dispatch_once_t onceToken;
    dispatch_once(&onceToken, ^{
        mediator = [[LGMediator alloc] init];
    });
    return mediator;
}

/*
 scheme://[target]/[action]?[params]
 url sample: aaa://targetA/actionB?id=1234
 */
- (id)performActionWithUrl:(NSURL *)url completion:(void (^)(NSDictionary *))completion
{
    NSMutableDictionary *params = [[NSMutableDictionary alloc] init];
    NSString *urlString = [url query];
    for (NSString *param in [urlString componentsSeparatedByString:@"&"]) {
        NSArray *elts = [param componentsSeparatedByString:@"="];
        if([elts count] < 2) continue;
        [params setObject:[elts lastObject] forKey:[elts firstObject]];
    }

    // 安全防护：防止黑客通过远程 URL 调用本地敏感模块
    NSString *actionName = [url.path stringByReplacingOccurrencesOfString:@"/" withString:@""];
    if ([actionName hasPrefix:@"native"]) {
        return @(NO);
    }

    id result = [self performTarget:url.host
                             action:actionName
                             params:params
                  shouldCacheTarget:NO];
    if (completion) {
        if (result) {
            completion(@{@"result":result});
        } else {
            completion(nil);
        }
    }
    return result;
}

- (id)performTarget:(NSString *)targetName
             action:(NSString *)actionName
             params:(NSDictionary *)params
  shouldCacheTarget:(BOOL)shouldCacheTarget
{
    NSString *swiftModuleName = params[kLGMediatorParamsKeySwiftTargetModuleName];

    // Step 1: 拼接 Target 类名（支持 Swift Module）
    NSString *targetClassString = nil;
    if (swiftModuleName.length > 0) {
        targetClassString = [NSString stringWithFormat:@"%@.Target_%@",
                             swiftModuleName, targetName];
    } else {
        targetClassString = [NSString stringWithFormat:@"Target_%@", targetName];
    }

    // Step 2: 从缓存中获取或创建 Target 实例
    NSObject *target = self.cachedTarget[targetClassString];
    if (target == nil) {
        Class targetClass = NSClassFromString(targetClassString);
        target = [[targetClass alloc] init];
    }

    // Step 3: 拼接 Action 方法名
    NSString *actionString = [NSString stringWithFormat:@"Action_%@:", actionName];
    SEL action = NSSelectorFromString(actionString);

    // Step 4: 三级容错处理
    if (target == nil) {  // ⚠️ 第一级：Target 不存在
        [self NoTargetActionResponseWithTargetString:targetClassString
                                     selectorString:actionString
                                       originParams:params];
        return nil;
    }

    if (shouldCacheTarget) {
        self.cachedTarget[targetClassString] = target;
    }

    if ([target respondsToSelector:action]) {  // ✅ 正常调用
        return [self safePerformAction:action target:target params:params];
    } else {  // ⚠️ 第二级：Action 不存在
        SEL notFoundAction = NSSelectorFromString(@"notFound:");
        if ([target respondsToSelector:notFoundAction]) {
            return [self safePerformAction:notFoundAction
                                    target:target
                                    params:params];
        } else {  // ⚠️ 第三级：notFound 也不存在
            [self NoTargetActionResponseWithTargetString:targetClassString
                                         selectorString:actionString
                                           originParams:params];
            [self.cachedTarget removeObjectForKey:targetClassString];
            return nil;
        }
    }
}

- (void)releaseCachedTargetWithTargetName:(NSString *)targetName
{
    NSString *targetClassString = [NSString stringWithFormat:@"Target_%@", targetName];
    [self.cachedTarget removeObjectForKey:targetClassString];
}

#pragma mark - private methods
- (void)NoTargetActionResponseWithTargetString:(NSString *)targetString
                                selectorString:(NSString *)selectorString
                                  originParams:(NSDictionary *)originParams
{
    // 调用固定的 Target_NoTargetAction 进行统一处理
    SEL action = NSSelectorFromString(@"Action_response:");
    NSObject *target = [[NSClassFromString(@"Target_NoTargetAction") alloc] init];

    NSMutableDictionary *params = [[NSMutableDictionary alloc] init];
    params[@"originParams"] = originParams;
    params[@"targetString"] = targetString;
    params[@"selectorString"] = selectorString;

    [self safePerformAction:action target:target params:params];
}

- (id)safePerformAction:(SEL)action target:(NSObject *)target params:(NSDictionary *)params
{
    // ① 获取方法签名：包含返回值类型、参数数量及类型等信息
    NSMethodSignature* methodSig = [target methodSignatureForSelector:action];
    if(methodSig == nil) {
        return nil;
    }

    // ② 获取返回值类型的 C 字符串编码
    // @encode(void)     → "v"
    // @encode(NSInteger)→ "q"（64位）或 "i"（32位）
    // @encode(BOOL)     → "B"（现代）或 "c"（旧版）
    // @encode(CGFloat)  → "d"（64位）或 "f"（32位）
    // @encode(NSUInteger)→ "Q"（64位）或 "I"（32位）
    // @encode(id)       → "@"
    const char* retType = [methodSig methodReturnType];

    // ③ 根据不同的返回值类型分别处理
    // 为什么要用 strcmp 而不用 performSelector?
    // performSelector: 只能返回 id 类型（对象指针）
    // 对于 NSInteger/BOOL/CGFloat 等基础类型，必须用
    // NSInvocation 的 getReturnValue: 才能正确取值

    // ③-a 返回值类型为 void（无返回值）
    if (strcmp(retType, @encode(void)) == 0) {
        // NSInvocation 可以调用任意方法，不限于返回 id 类型
        NSInvocation *invocation = [NSInvocation invocationWithMethodSignature:methodSig];
        [invocation setArgument:&params atIndex:2]; // index 0=self, 1=_cmd, 2=第一个参数
        [invocation setSelector:action];
        [invocation setTarget:target];
        [invocation invoke];
        return nil; // void 无返回值
    }

    // ③-b 返回值类型为 NSInteger（64位="q", 32位="i"）
    if (strcmp(retType, @encode(NSInteger)) == 0) {
        NSInvocation *invocation = [NSInvocation invocationWithMethodSignature:methodSig];
        [invocation setArgument:&params atIndex:2];
        [invocation setSelector:action];
        [invocation setTarget:target];
        [invocation invoke];
        NSInteger result = 0;
        [invocation getReturnValue:&result]; // 从返回值缓冲区读取 NSInteger
        return @(result); // 包装为 NSNumber 返回
    }

    // ③-c 返回值类型为 BOOL（"B" 或 "c"）
    if (strcmp(retType, @encode(BOOL)) == 0) {
        NSInvocation *invocation = [NSInvocation invocationWithMethodSignature:methodSig];
        [invocation setArgument:&params atIndex:2];
        [invocation setSelector:action];
        [invocation setTarget:target];
        [invocation invoke];
        BOOL result = 0;
        [invocation getReturnValue:&result];
        return @(result);
    }

    // ③-d 返回值类型为 CGFloat（64位="d", 32位="f"）
    if (strcmp(retType, @encode(CGFloat)) == 0) {
        NSInvocation *invocation = [NSInvocation invocationWithMethodSignature:methodSig];
        [invocation setArgument:&params atIndex:2];
        [invocation setSelector:action];
        [invocation setTarget:target];
        [invocation invoke];
        CGFloat result = 0;
        [invocation getReturnValue:&result];
        return @(result);
    }

    // ③-e 返回值类型为 NSUInteger（"Q" 或 "I"）
    if (strcmp(retType, @encode(NSUInteger)) == 0) {
        NSInvocation *invocation = [NSInvocation invocationWithMethodSignature:methodSig];
        [invocation setArgument:&params atIndex:2];
        [invocation setSelector:action];
        [invocation setTarget:target];
        [invocation invoke];
        NSUInteger result = 0;
        [invocation getReturnValue:&result];
        return @(result);
    }

    // ③-f 兜底：返回值类型为 id（对象类型）
    // 用 performSelector: 处理，因为 performSelector 本身返回 id
    // 关闭 ARC 的 leak 警告（performSelector 编译器无法知道返回值的内存管理语义）
#pragma clang diagnostic push
#pragma clang diagnostic ignored "-Warc-performSelector-leaks"
    return [target performSelector:action withObject:params];
#pragma clang diagnostic pop
}

#pragma mark - getters and setters
- (NSMutableDictionary *)cachedTarget
{
    if (_cachedTarget == nil) {
        _cachedTarget = [[NSMutableDictionary alloc] init];
    }
    return _cachedTarget;
}

@end
```

#### 核心设计分析

**1. 三级容错机制**

```
调用 performTarget:action:params:
  │
  ├─ Step 1: Target 类是否存在？
  │    ❌ → NoTargetActionResponse（调用 Target_NoTargetAction 统一处理）
  │    ✅ → 创建/获取 Target 实例
  │
  ├─ Step 2: Action 方法是否存在？
  │    ❌ → 尝试调用 Target 的 notFound: 方法
  │    ✅ → safePerformAction 调用
  │
  └─ Step 3: notFound: 也不存在？
       ❌ → NoTargetActionResponse + 清理缓存
```

保证了任何调用路径都不会导致崩溃。

**2. 返回值类型处理**

`safePerformAction:` 对 5 种返回值类型分别处理：

| 返回值类型 | 处理方式 | 原因 |
|-----------|---------|------|
| `void` | NSInvocation，不取返回值 | 无返回值 |
| `NSInteger` | NSInvocation + getReturnValue | `performSelector` 无法返回基础类型 |
| `BOOL` | 同上 | 同上 |
| `CGFloat` | 同上 | 同上 |
| `NSUInteger` | 同上 | 同上 |
| `id`（其他） | `performSelector:withObject:` | 返回对象类型，直接使用 |

**3. URL Scheme 安全防护**

```objc
if ([actionName hasPrefix:@"native"]) {
    return @(NO);  // 禁止远程调用 native 开头的方法
}
```

防止黑客通过 URL Scheme 调用本地敏感模块。

**4. Swift 模块名支持**

```objc
if (swiftModuleName.length > 0) {
    targetClassString = [NSString stringWithFormat:@"%@.Target_%@",
                         swiftModuleName, targetName];
}
```

`NSClassFromString(@"MyModule.Target_Order")` 是 Swift 类的标准命名方式。

#### CTMediator 的优缺点

| 优点 | 缺点 |
|------|------|
| ✅ 无需任何注册（运行时动态解析） | ❌ Target/Action 是字符串，编译不检查 |
| ✅ 完全解耦，调用方不 import 任何类 | ❌ 参数类型不安全（NSDictionary） |
| ✅ 三级容错，不会崩溃 | ❌ 需要为每个 Target 写 Category 才能类型安全 |
| ✅ 支持 URL Scheme 外部调用 | ❌ 大量使用 Runtime，调试困难 |
| ✅ 支持 Swift | ❌ cachedTarget 可能引起内存问题 |
| ✅ 处理 5 种返回值类型 | |

### 4.2 MGJRouter 源码解析

#### 核心实现

```objc
// MGJRouter.m （简化核心代码）

@interface MGJRouter ()
@property (nonatomic, strong) NSMutableDictionary *routes;  // URL Pattern → Handler
@end

@implementation MGJRouter

// ═══════ 注册 URL Pattern ═══════
+ (void)registerURLPattern:(NSString *)URLPattern
                 toHandler:(MGJRouterHandler)handler {

    [[self sharedInstance] addURLPattern:URLPattern andHandler:handler];
}

- (void)addURLPattern:(NSString *)URLPattern
          andHandler:(MGJRouterHandler)handler {

    // 解析 URL Pattern，提取路径参数占位符（:id 等）
    NSMutableDictionary *subRoutes = [self parseURLPattern:URLPattern];

    // 将 handler 存入 routes 字典
    // key: 解析后的 pattern（如 app://user/detail/:id）
    // value: handler block
    if (subRoutes[@"_handler_"] == nil) {
        subRoutes[@"_handler_"] = [handler copy];
    }
}

// ═══════ 解析 URL Pattern（关键代码 ═══════
// 将 "app://user/detail/:id" 解析为路径片段
// 并用正则提取 :id 等参数占位符
- (NSMutableDictionary *)parseURLPattern:(NSString *)URLPattern {
    // 1. 按 / 拆分路径
    NSArray *pathComponents = [URLPattern componentsSeparatedByString:@"/"];

    // 2. 遍历路径片段，识别 :param 形式的参数占位符
    NSMutableDictionary *route = [NSMutableDictionary dictionary];
    for (NSString *component in pathComponents) {
        if ([component hasPrefix:@":"]) {
            // 如 :id → 提取出参数名 id
            // 实际请求时替换为真实值
        }
    }
    return route;
}

// ═══════ 打开 URL ═══════
+ (void)openURL:(NSString *)URL
   withUserInfo:(NSDictionary *)userInfo
     completion:(void(^)(id result))completion {

    // 1. 解析 URL
    NSURL *parsedURL = [NSURL URLWithString:URL];
    NSString *scheme = parsedURL.scheme;    // app
    NSString *host = parsedURL.host;        // user
    NSString *path = parsedURL.path;        // /detail/123

    // 2. 匹配注册的 Pattern
    NSDictionary *route = [self findMatchRoute:URL];

    // 3. 提取参数
    //    从 URL 路径中提取 :id = 123
    //    从 URL query 中提取 source = home
    //    从 userInfo 中提取字典参数
    NSMutableDictionary *routerParams = [NSMutableDictionary dictionary];
    routerParams[@"id"] = extractedValue;                       // 路径参数
    routerParams[@"source"] = queryValue;                       // query 参数
    routerParams[MGJRouterParameterUserInfo] = userInfo;        // 字典参数
    routerParams[MGJRouterParameterCompletion] = completion;    // 回调

    // 4. 执行 handler
    MGJRouterHandler handler = route[@"_handler_"];
    if (handler) {
        handler(routerParams);
    }
}

// ═══════ 查找匹配的注册 Pattern ═══════
- (NSDictionary *)findMatchRoute:(NSString *)URL {
    // 遍历 routes 字典，用正则匹配 URL
    // 支持：静态路径 /user/list
    // 支持：动态参数 /user/:id
    // 支持：通配符 /user/*
    for (NSString *pattern in self.routes) {
        NSString *regex = [self patternToRegex:pattern];
        // 用 NSRegularExpression 匹配
    }
    return nil;
}

// ═══════ URL Pattern 转正则 ═══════
- (NSString *)patternToRegex:(NSString *)pattern {
    // 将 app://user/:id 转为 ^app://user/([^/]+)$
    // 将 app://user/* 转为 ^app://user/.*$
    return regexString;
}

@end
```

#### MGJRouter 的运行流程

```
注册时：
  registerURLPattern:@"app://user/:id" → handler
  → 解析 Pattern，存入 routes 字典
  → routes = @{ @"app://user/:id" → handler_block }

调用时：
  openURL:@"app://user/detail/123?source=home"
  → ① 解析 URL，分离 scheme/host/path/query
  → ② 正则匹配注册的 Pattern
  → ③ 从 URL 路径提取 :id = @"123"
  → ④ 从 URL query 提取 source = @"home"
  → ⑤ 合并 userInfo + completion
  → ⑥ 生成 routerParameters 字典
  → ⑦ 调用 handler(routerParameters) 执行回调
```

#### MGJRouter 的优缺点

| 优点 | 缺点 |
|------|------|
| ✅ 完全解耦，URL 统一管理 | ❌ 参数全部是 NSString/NSDictionary |
| ✅ 可以处理外部 URL Scheme（推送、扫码跳转） | ❌ 注册散落在各处的 +load 中 |
| ✅ 支持通配符和参数占位符 | ❌ 没有返回值，只能用 completion 回调 |
| ✅ 支持异步 completion | ❌ URL 拼写错误编译不报错 |

### 4.3 Protocol-Class 方案源码解析（ServiceLocator）

Protocol-Class 方案的核心是维护一个 **Protocol → Class** 的映射表，通过 Protocol 获取对应的 Class 实例。

#### 核心实现

```objc
// ServiceLocator.h
#import <objc/runtime.h>

@interface ServiceLocator : NSObject

// 注册：将 Protocol 与 Class 绑定
+ (void)registerService:(Protocol *)serviceProto class:(Class)serviceClass;

// 获取：通过 Protocol 获取对应类的实例
+ (id)serviceForProtocol:(Protocol *)serviceProto;

// 获取：带创建 block 的版本（延迟初始化）
+ (void)registerService:(Protocol *)serviceProto
           withCreation:(id(^)(void))creationBlock;

@end
```

```objc
// ServiceLocator.m
#import "ServiceLocator.h"

@interface ServiceLocator ()
@property (nonatomic, strong) NSMutableDictionary *serviceMap;     // Protocol → Class
@property (nonatomic, strong) NSMutableDictionary *instanceMap;    // Class → Instance（单例缓存）
@property (nonatomic, strong) NSMutableDictionary *blockMap;       // Protocol → CreationBlock
@end

@implementation ServiceLocator

// ═══════ 单例 ═══════
+ (instancetype)shared {
    static ServiceLocator *instance;
    static dispatch_once_t onceToken;
    dispatch_once(&onceToken, ^{
        instance = [[ServiceLocator alloc] init];
        instance.serviceMap = [NSMutableDictionary dictionary];
        instance.instanceMap = [NSMutableDictionary dictionary];
        instance.blockMap = [NSMutableDictionary dictionary];
    });
    return instance;
}

// ═══════ 注册 Protocol → Class ═══════
+ (void)registerService:(Protocol *)serviceProto class:(Class)serviceClass {
    // Step 1: 校验 Class 是否遵守了 Protocol
    if (![serviceClass conformsToProtocol:serviceProto]) {
        NSLog(@"⚠️ %@ 没有遵守 %@ 协议", NSStringFromClass(serviceClass), NSStringFromProtocol(serviceProto));
        return;
    }

    // Step 2: 存入映射字典
    NSString *key = NSStringFromProtocol(serviceProto);
    [[self shared].serviceMap setObject:serviceClass forKey:key];
}

// ═══════ 获取 Protocol 对应的实例 ═══════
+ (id)serviceForProtocol:(Protocol *)serviceProto {
    NSString *key = NSStringFromProtocol(serviceProto);

    // Step 1: 查创建 block 缓存
    id (^creationBlock)(void) = [[self shared].blockMap objectForKey:key];
    if (creationBlock) {
        return creationBlock();
    }

    // Step 2: 查 Class 映射
    Class serviceClass = [[self shared].serviceMap objectForKey:key];
    if (!serviceClass) {
        NSLog(@"⚠️ Protocol %@ 未注册", key);
        return nil;
    }

    // Step 3: 查实例缓存（单例模式）
    NSString *classKey = NSStringFromClass(serviceClass);
    id instance = [[self shared].instanceMap objectForKey:classKey];
    if (!instance) {
        instance = [[serviceClass alloc] init];
        [[self shared].instanceMap setObject:instance forKey:classKey];
    }

    return instance;
}

// ═══════ 注册带创建 block 的版本 ═══════
+ (void)registerService:(Protocol *)serviceProto
           withCreation:(id (^)(void))creationBlock {
    NSString *key = NSStringFromProtocol(serviceProto);
    [[self shared].blockMap setObject:creationBlock forKey:key];
}

// ═══════ 移除注册（用于测试或重置） ═══════
+ (void)unregisterService:(Protocol *)serviceProto {
    NSString *key = NSStringFromProtocol(serviceProto);
    [[self shared].serviceMap removeObjectForKey:key];
    [[self shared].blockMap removeObjectForKey:key];
}

@end
```

#### 使用示例

```objc
// 1. 定义协议
@protocol UserService <NSObject>
- (UserModel *)getUserById:(NSString *)userId;
- (void)loginWithAccount:(NSString *)account password:(NSString *)password;
@end

// 2. 实现协议
```

#### BeeHive 的协议注册原理

BeeHive 是阿里巴巴开源的 Protocol-Class 组件化方案，它的核心实现更复杂：

```objc
// BeeHive 简化核心代码
@interface BHModuleManager : NSObject

@property (nonatomic, strong) NSMutableDictionary<NSString *, id> *moduleInstanceMap;

@end

@implementation BHModuleManager

// BeeHive 通过读取 plist 文件或扫描 __DATA 段 + __BeehiveOBJC 段来注册

    // 读取 BeeHive.bundle 中的 plist 配置文件
    // 或扫描二进制文件中 __BeehiveOBJC 段的元数据
}

- (void)registerService:(Protocol *)proto implClass:(Class)implClass {
    NSString *key = NSStringFromProtocol(proto);
    [self.serviceMap setObject:implClass forKey:key];
}

- (id)createService:(Protocol *)serviceProto {
    NSString *key = NSStringFromProtocol(serviceProto);
    Class implClass = self.serviceMap[key];
    if (!implClass) return nil;

    // 支持单例模式（通过协议中的 @optional 方法判断）
    id instance = [[implClass alloc] init];

}
```

## 五、组件化实施步骤

### 4.1 组件拆分原则

```
1. 按业务拆分：每个业务线一个组件
2. 按功能拆分：网络、图片、UI 等基础功能独立
3. 单向依赖：业务层 → 基础层（严禁反向依赖）
4. 接口稳定：对外接口一旦确定，尽量不做不兼容修改
5. 独立编译：每个组件可独立编译测试
```

| **单仓库（Mono-Repo）** | 所有组件在一个仓库 | 统一版本，跨组件修改方便 | 仓库庞大，权限难控 |

## 八、面试题

### 1. 什么是组件化？为什么要做组件化？

组件化是将一个应用拆分为多个独立的可复用组件的架构方式。目的：
- 代码解耦，提高可维护性
- 各组件可独立开发、测试、部署
- 复用已有组件，减少重复开发
- 编译加速（增量编译）
- 团队分工协作更清晰

### 2. 组件间通信有哪些方式？

URL Router、Target-Action、Protocol-Class。推荐 Protocol-Class 方案（编译期类型安全）。

### 3. 组件化后如何管理页面跳转？

统一通过路由中间件跳转，调用方只依赖路由协议，不依赖目标页面。

### 4. CTMediator 的原理是什么？

基于 Runtime 的 Target-Action 模式，通过 `performSelector:withObject:` 动态调用 Target 的 Action 方法，实现完全解耦。

### 5. 组件化的粒度如何把握？

- 业务组件按业务线拆分（登录、订单、消息等）
- 基础组件按功能拆分（网络、存储、UI 等）
- 粒度太细（管理成本高），太粗（复用度低）

### 6. 组件化后重复代码怎么处理？

下沉到基础组件是首选方案，少量代码可容忍重复。

### 7. 组件化对编译速度有什么影响？

初期拆分后编译变慢（多 Target），可通过二进制化（Framework 预编译）加速。

### 8. 小型项目需要组件化吗？

不需要。小型项目用模块化即可，过度设计会增加开发和维护成本。
